# Code Review

## Points forts
- La séparation claire entre la logique d'état (contextes `UiContext` et `AnimationContext`) et les composants de présentation facilite la lecture et le test de l'application. L'utilisation de hooks personnalisés comme `useSceneDrag` et `useScenePanZoom` encapsule proprement des comportements complexes (glisser-déposer, zoom/panoramique) sans alourdir les composants.【F:src/context/UiContext.tsx†L1-L194】【F:src/hooks/useSceneDrag.ts†L1-L109】【F:src/hooks/useScenePanZoom.ts†L1-L85】

## Problèmes critiques
1. **Le bouton "Bring forward" déplace les éléments dans le mauvais sens.** La fonction `bringForward` insère le prochain frère *avant* l'élément courant (`insertBefore(item.el.nextSibling, item.el)`), ce qui fait reculer l'élément sélectionné au lieu de l'avancer. Il faut insérer l'élément courant avant `nextSibling.nextSibling` (ou `null`) pour obtenir l'effet recherché.【F:src/context/UiContext.tsx†L89-L95】
2. **Le rechargement d'un projet laisse des éléments fantômes dans `sceneItems`.** Lors de l'événement `project:load`, les noeuds DOM sont supprimés mais le tableau `sceneItems` du contexte n'est jamais remis à zéro avant d'ajouter les nouveaux éléments. Les anciennes entrées persistent donc dans les panneaux Inspector/Layers avec des références vers des éléments DOM supprimés. Il faudrait réinitialiser l'état (exposer `setSceneItems` ou fournir un `resetSceneItems`).【F:src/components/SvgScene.tsx†L251-L338】【F:src/context/UiContext.tsx†L73-L88】
3. **Impossible de pan/zoomer tant qu'aucun décor n'a été chargé.** `useScenePanZoom` ignore les événements de molette si `viewSizeRef.current` est nul. Or c'est le cas au démarrage avant que `setDecor` n'ait défini les dimensions. Résultat : le zoom/panoramique est bloqué jusqu'au chargement d'un décor. Remplacer ce garde par un fallback (utiliser la boîte englobante actuelle) résoudrait le problème.【F:src/hooks/useScenePanZoom.ts†L56-L81】
4. **La sélection depuis le panneau Layers n'actualise pas l'Inspector.** `LayerItem` se contente d'appeler `setSelectedPuppet` sans mettre à jour `selectedItemId`. L'Inspector affiche donc toujours l'ancien élément sélectionné, ce qui surprend l'utilisateur. Le panneau devrait appeler aussi `setSelectedItemId` (et éventuellement `setSelectedLimb("")`).【F:src/components/LayerItem.tsx†L14-L33】

## Améliorations supplémentaires suggérées
- Lors de l'ajout d'un `sceneItem`, le libellé est modifié in place (`item.label = …`), ce qui peut surprendre l'appelant. Un clonage éviterait les mutations implicites.【F:src/context/UiContext.tsx†L73-L81】
- Le `setTimeout` de 150 ms utilisé pour réappliquer les rotations des membres après chargement d'un projet est fragile : l'intervalle peut être insuffisant sur des machines lentes ou inutilement long. On pourrait écouter l'événement `onReady` du composant `SvgPuppetInlineSimple` pour appliquer immédiatement les transformations.【F:src/components/SvgScene.tsx†L286-L303】
